# نقشه اجرایی AI Router Studio
آخرین بازبینی: 2026-10-22
شاخه کاری: `ai-router-v1`

## 1. هدف محصول
ساخت یک ارکستراتور هوش مصنوعی که درخواست طبیعی کاربر را به طرح شفاف و قابل‌ویرایش تبدیل کند، Taskها را به ابزار/مدل مناسب بسپارد، هزینه را صفر نگه دارد و تنها پس از تأیید کاربر اجرای واقعی را شروع کند.

## 2. محدودیت‌های قطعی
- سقف هزینه نسخه فعلی صفر تومان است؛ Provider پولی فراخوانی نمی‌شود.
- هیچ Task موفق اعلام نمی‌شود مگر پاسخ واقعی و قابل بررسی دریافت شده باشد.
- تغییر درخواست/تنظیمات Preview قبلی را باطل می‌کند.
- فقط مدل‌های محلی قابل انتخاب‌اند؛ مدل‌های دارای پسوند `:cloud` هم در رابط فیلتر می‌شوند و هم در Backend رد می‌شوند. هیچ مدلی خودکار دانلود نمی‌شود.
- اولین ایجنت فقط متن تولید می‌کند؛ وب‌گردی، اجرای کد، دسترسی فایل و تغییر پروژه ندارد.
- هیچ کلید یا توکنی داخل مخزن Git قرار نمی‌گیرد.
- ویژگی‌های Instagram/Meta آینده باید از API رسمی و رضایت کاربر استفاده کنند.

## 3. وضعیت پیاده‌سازی
### انجام شده در شاخه کاری
- رابط فارسی RTL، Planner قاعده‌محور و Preview.
- Backend محلی Python استاندارد، SQLite، ذخیره تاریخچه و audit log.
- بررسی سرویس Ollama و مدل‌های نصب‌شده بدون تولید متن یا دانلود.
- adapter واقعی `POST /api/chat` با timeout و سقف پاسخ؛ درخواست از loopback عبور می‌کند و proxy محیط غیرفعال است.
- سیاست صفرهزینه به‌صورت دفاع در عمق: مدل‌های `:cloud` نه در انتخاب‌گر نمایش داده می‌شوند و نه درخواست مستقیم به آن‌ها پذیرفته می‌شود.
- endpoint اجرای مدل که fingerprint، تأیید طرح، بودجه صفر و نام دقیق مدل نصب‌شده را بررسی می‌کند.
- جدول SQLite برای وضعیت اجرای ایجنت `running / succeeded / failed`، خروجی، نام مدل و آمار توکن.
- کنترل رابط برای انتخاب مدل، تأیید صریح، اجرای متن و نمایش امن خروجی با `textContent`.
- تست خودکار برای رد طرح تأییدنشده، رد مدل نصب‌نشده و ثبت خروجی واقعی (با mock).

### هنوز انجام نشده یا تأیید نشده
- آزمایش مدل روی کامپیوتر کاربر؛ تست CI پاسخ مدل را mock می‌کند.
- benchmark سرعت/مصرف RAM و انتخاب خودکار مدل مناسب.
- وب‌گردی با منابع و citation؛ ایجنت نباید ادعای بررسی منابع زنده بکند.
- اجرای کد، تغییر امن فایل‌ها یا تست خودکار پروژه‌های ساخته‌شده.
- برنامه‌ریزی DAG و هماهنگی چند ایجنت.
- tokenizer دقیق، cache معنایی و سنجش صرفه‌جویی واقعی توکن.
- تولید تصویر، Instagram/Meta و انتشار عمومی Pages.

## 4. قرارداد ایجنت محلی V1
1. کاربر Preview می‌سازد.
2. برنامه با `GET /api/tags` فقط مدل‌های نصب‌شده را می‌خواند.
3. کاربر مدل را انتخاب و «تأیید طرح و اجرای ایجنت» را می‌زند.
4. Backend fingerprint، تأیید، بودجه صفر و مدل نصب‌شده را دوباره بررسی می‌کند.
5. فقط درخواست متنی به `http://127.0.0.1:11434/api/chat` فرستاده می‌شود.
6. پاسخ یا خطا در SQLite ذخیره می‌شود؛ خطا هرگز موفقیت اعلام نمی‌شود.

## 5. معماری
- رابط HTML/CSS/JS فعلی تا وقتی دلیل واقعی برای framework نیست حفظ شود.
- Backend محلی Python standard library؛ dependency جدید فقط در صورت نیاز اثبات‌شده.
- فقط Providerهای صریحاً مجاز و صفرهزینه؛ اتصال ابری پیش‌فرض خاموش بماند.
- LiteLLM/Dify/n8n تنها پس از اثبات نیاز بررسی شوند.
- دیتابیس/backup محلی در Git یا سایت عمومی منتشر نشوند.
